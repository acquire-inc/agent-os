# Phase 13 / Plan 01 — Candidate ATTACH implementation

## Goal

Reauthor 5 quarantined skill candidates and attach them to AgentOS seed scripts per Phase 11 decisions. Wave 1 authors skill files, Wave 2 attaches, Wave 3 verifies.

## Target sets (resolved from current seed scripts)

**T-critical (NEVER touched, 14 agents):** access-auditor, ad-claim-compliance, contract-drafter, contract-lifecycle-manager, decision-memo-drafter, discount-governor, offer-architect, offer-validator, pricing-architect, reinvestment-advisor, risk-register-keeper, secrets-rotation, security-anomaly-watchdog, tenant-isolation-tester

**prompt-injection-guardrail targets (3):** creative-miner, discovery-prep, lead-triage (all agents using `tool.browser` or `tool.connector.*`)

**output-quality-gate targets (4):** creative-studio, client-comms, weekly-report, content-engine

**scope-lock-discipline targets (3):** ad-ops, launcher, content-engine

**shadow-mode-discipline targets (15 non-T-critical propose agents):** agent-onboarder, call-summarizer, case-study-builder, client-comms, content-engine, creative-studio, dunning-manager, ea, knowledge-curator, launcher, memory-consolidator, onboarding-runner, save-play, skill-librarian, weekly-report

**cost-ceiling-discipline targets (48 non-T-critical agents):** all `acqu-*.ts` seed scripts EXCEPT the 14 T-critical list

## Wave 1 — Author 5 skill files

Each new `external/acqu-skills/<skill>/SKILL.md` is reauthored from scratch using the structure of existing AgentOS skills (`verification-before-completion/SKILL.md` as the canonical template). NO verbatim copy from the quarantine `agents/_candidates/<skill>/SKILL.md`. AgentOS-only framing — strip any "Cliently" references from the source.

Each file has: frontmatter (`name`, `description`), H1 title, Purpose section, Workflow section (numbered steps), Rules section (bullet list), Output contract section.

After Wave 1, run shingle check (Phase 11 logic): for each new skill, compare against the quarantine source via 8-word shingles after whitespace+case normalization. Threshold > 10 shared shingles = fail.

## Wave 2 — Attach to seed scripts

Each seed script edit adds one line to the `skills: [...]` array:

```ts
{ key: "<skill-key>", name: "<Title Case>" },
```

Edits are additive only. No removals. No reordering of existing skills. No tool/autonomy/model changes.

Per-target wave 2 grouping (each row is one parallel batch):

| Skill | Seed files to touch |
|---|---|
| prompt-injection-guardrail | 3 files (creative-miner, discovery-prep, lead-triage) |
| output-quality-gate | 4 files (creative-studio, client-comms, weekly-report, content-engine) |
| scope-lock-discipline | 3 files (ad-ops, launcher, content-engine) |
| shadow-mode-discipline | 15 files (the propose-tier non-T-critical list above) |
| cost-ceiling-discipline | 48 files (all non-T-critical) |

Note: content-engine receives 4 new skills (prompt-injection-guardrail not — no browser; output-quality-gate, scope-lock-discipline, shadow-mode-discipline, cost-ceiling-discipline = 4). Other multi-skill agents follow the same per-skill logic.

Threshold of >10 shared 8-word shingles is the Phase 11-validated cutoff; a single legitimate near-miss is acceptable.
- Seed-script count (48 cost-ceiling targets) is high. Mitigation: scripted edit via shared snippet ensures consistency.
