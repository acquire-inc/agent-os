# Phase 12 / Plan 01 — AgentOS safety regressions

## Goal

Close two forward-looking safety regressions surfaced in Phase 11 code review (WR-06). Both are AgentOS-internal hardening that pin existing safety invariants with regression tests. No production code edits — only new test files plus the `package.json` script wiring to run them.

## Test conventions (read before authoring tests)

This codebase does **not** use Vitest. Tests are hand-rolled:
- File lives **alongside** source (e.g. `hydrate.ts` → `hydrate.immutability.test.ts`), not under `__tests__`
- Hand-rolled `assert(cond, msg)` + `console.log` / `console.error` with `passed` / `failed` counters (copy the pattern from `architect.test.ts` lines 6-31)
- Each test file ends with `process.exit(failed === 0 ? 0 : 1)`
- Tests are added to `packages/core/package.json` as new `test:<name>` script entries that `tsx` the file directly
- Package name is `@agent-os/core`

## Risk

- **Path resolution in Task 2** — relative path `../../../../apps/runner/src/execute.ts` from `packages/core/src/router/` must resolve. Verified during plan authoring against current repo layout. If a future restructure breaks this path, the test fails loud with the missing-file error, not silently.
